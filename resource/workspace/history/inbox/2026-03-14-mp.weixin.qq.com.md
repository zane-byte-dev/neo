 让 AI 真的“记住你”：一套零成本的三层记忆系统（OpenClaw 实战复盘） 适用对象：在用 Agent / 多 Agent 做真实项目的人；或者你已经受够了“聊完就忘、反复解释”的工作流。 原文来自 Ray Wang 在 X（推特）的实战分享，核心是一句话： 上下文窗口不等于记忆。想让 Agent 记住，必须把关键信息写进文件。 一、为什么你的 Agent 总在“失忆”？ 很多人以为：只要对话够长，模型就能一直记得。 但现实是： LLM 的上下文窗口是临时工作台，不是长期记忆。 对话变长后，系统会做压缩（compaction），早期内容被丢弃 一旦 session 结束，Agent 下次“醒来”就像重启一样 多渠道（Telegram、Discord、微信……）之间更是互相看不到 结果就是： 同一个建议反复提 关键决策被忘掉，团队重复讨论 你总在“重新讲一遍背景” 文中给了一个非常直观的例子： Session 1: 做了重要决策 A → 没写进文件 → Compaction Session 2: Agent 完全不知道决策 A 的存在 → 重复讨论 → 浪费时间 所以才有这条原则： 文件 = 事实来源。你不写进文件的东西 = 你从来不知道的东西。 把 Agent 的“记忆”从脑子里，搬到磁盘上。 二、整体思路：三层记忆 + 一个“主动遗忘”机制 这套系统把信息分层管理： 短期：NOW.md（工作台） 中期：每日记忆日志（事件流水） 长期：可复用知识库（Lessons/Decisions/People…） 再加一个关键机制： 定期归档冷数据（让系统会“遗忘”） 。 原文的结构图（文本版）大意如下： 事件/对话 → 实时写入每日日志 每晚反思：从日志里提炼出“经验/决策/画像”写入知识库 每周 GC：把过期且不再被引用的内容归档到冷存储 这样做的目标不是“存得越多越好”，而是： 写得进（可持久化） 找得到（可检索） 不过载（会衰减/会遗忘） 三、短期记忆：NOW.md（唯一允许覆写的文件） NOW.md 是状态面板 ，用来告诉 Agent： 我们的目标是什么 今天重点是什么 谁在做什么 当前卡点在哪里 它的关键点是： 每次 heartbeat（心跳任务）直接覆写 ，不追加 只保留“今天必须知道”的内容 对抗 compaction：上下文被压缩后，Agent 先读 NOW.md 就能快速恢复状态 示例（可直接照抄）： # NOW.md - Workbench > **Mission**: 你的核心目标 ## Today (MM/DD) - ✅ 已完成的重要事项 - ⚠️ 需要关注的问题 ## P0 Priorities | # | Item | Status | Owner | |---|------|--------|-------| | P0 | 最重要的事 | 进行中 | Agent A | | P1 | 次重要的事 | 待开始 | Agent B | ## Agent Status | Agent | Focus | |------|-------| | Agent A | 当前任务 | | Agent B | 当前任务 | --- *Updated: YYYY-MM-DD HH:MM* 一句话总结： NOW.md 是“今天的驾驶舱”。 四、中期记忆：每日日志（append-only，永不覆写） 每日日志是“发生了什么”的原始流水账。 文件路径： memory/YYYY-MM-DD.md 记录粒度：事件、完成、变更、发现 规则： 只追加、不覆写 推荐统一格式： ### 14:30 — 完成了数据库迁移 迁移 PostgreSQL 从 v14 到 v16，耗时 45 分钟。 关键步骤：先备份 → 升级 → 验证数据完整性。 无数据丢失。 为什么必须“宁多勿少”？ 因为 session 之间隔离：你不立刻写，另一个 session 永远看不到 因为人也会忘：日志是你和 Agent 的共同证据 五、长期记忆：知识库（可复用的“蒸馏层”） 长期记忆不是流水账，而是从日志中提炼出的“可复用知识”。 原文建议用一个索引文件做导航枢纽： memory/INDEX.md ：启动时先扫它，按需加载 并把知识按类型拆目录： decisions/ ：重要决策（永久保留） lessons/ ：经验教训（按主题沉淀） people/ ：用户画像、联系人、Agent 画像（永久保留） projects/ ：项目状态 preferences/ ：偏好与边界（永久保留） reflections/ ：每日反思 actions/ ：任务生命周期 一个推荐的目录树： workspace/ ├── NOW.md ├── AGENTS.md ├── HEARTBEAT.md └── memory/ ├── INDEX.md ├── YYYY-MM-DD.md ├── decisions/ ├── lessons/ ├── people/ ├── projects/ ├── preferences/ ├── reflections/ ├── actions/ └── .archive/ 1）给知识文件加“元数据”（frontmatter） 为了让 Agent 知道哪些内容可信、哪些可能过时，文中要求在 lessons/ people/ decisions/ 里的文件加 YAML frontmatter，例如： --- title: "Cron 调度纪律" date: 2026-02-13 category: lessons priority: 🔴 status: active last_verified: 2026-02-26 tags: [cron, automation, reliability] --- 重点字段含义： priority ：重要性（影响检索排序、归档保护） status ：是否 active / superseded / conflict last_verified ：上次确认仍然正确的日期（做“过时提醒”） 2）写入前先读：CRUD 验证 长期记忆最怕“记忆幻觉”：写错、写重复、写矛盾。 所以文中强调： 写知识库前必须先读旧内容，然后决定是： NOOP：已有内容覆盖 → 不写 ADD：新增一个段落 UPDATE：旧版标记 superseded，再追加新版 CONFLICT：两版都保留，并标记冲突，等人工裁决 六、把“写日志”自动化：一个带时间戳的脚本 手动写时间很容易出错（甚至被 Agent “编造时间”）。 文中给了一个脚本 memlog.sh ，作用是： 自动取系统时间 追加到当天日志 永不覆盖历史内容 （原文脚本如下，可直接用） #!/usr/bin/env bash # memlog.sh — 自动时间戳的日志追加工具 # 用法: memlog.sh "Title" "Content body" set -euo pipefail MEMORY_DIR="${MEMORY_DIR:-/path/to/workspace/memory}" TODAY=$(TZ=Asia/Shanghai date +%Y-%m-%d) NOW=$(TZ=Asia/Shanghai date +%H:%M) FILE="$MEMORY_DIR/$TODAY.md" TITLE="${1:?Usage: memlog.sh \"Title\" \"Body\"}" BODY="${2:-}" # 如果文件不存在，创建带日期标题的文件 if [[ ! -f "$FILE" ]]; then printf "# %s\n" "$TODAY" > "$FILE" fi # 追加带时间戳的条目 { printf "\n### %s — %s\n" "$NOW" "$TITLE" [[ -n "$BODY" ]] && printf "\n%s\n" "$BODY" } >> "$FILE" echo "✓ Logged to $TODAY.md at $NOW" 七、为什么必须“让记忆会衰减”（主动遗忘） 很多人的记忆系统会死在一个问题上： 只进不出，最后被自己淹没。 原文提到 30 天就能积累上百个 Markdown 文件。如果不做衰减： 检索噪音变大：向量搜索会捞出很多“老但相似”的内容 启动扫描变慢：索引文件越来越长 索引膨胀：搜索库也会越来越大 作者借用了“艾宾浩斯遗忘曲线”的思路： 遗忘不是 bug，是 feature。 做法是引入“温度（Temperature）”概念： 新、常被引用、优先级高 → 热（Hot），保留在活跃索引 有点旧但还可能用 → 温（Warm），保留但降权 很旧且没被引用 → 冷（Cold），移入 .archive/ （冷存储，不参与索引） 并且利用一个简单但实用的技巧： .archive/ 以前缀点号开头 搜索引擎扫描时默认跳过隐藏目录 一句话总结： 先提炼，再遗忘。 八、最小可用版本：先跑起来再逐层加 如果你现在就想落地，不用一次性把所有组件都做完。 文中给的“阶段 0”最小可用配置是 3 个文件： NOW.md AGENTS.md （告诉 Agent 记忆规则） memory/YYYY-MM-DD.md （每日日志） 就能立刻解决 80% 的“跨 session 失忆”。 然后再按周迭代： 第 1 周：加 INDEX.md 、加 lessons/ decisions/ 第 2 周：加 frontmatter、加 nightly reflection（提炼与验证） 第 3 周：加语义搜索、加 GC（归档） 第 4 周：多 Agent 记忆聚合 结语：把“记忆”当成基础设施 这篇分享最值得记住的不是某个脚本、某个目录结构，而是这套心法： 上下文只是工作台 文件才是事实仓库 写入要自动化，知识要验证 系统要会遗忘，才能长期高效 参考来源 Ray Wang（@wangray）X 帖子：OpenClaw 记忆系统实战（链接： https://x.com/wangray/status/2027034737311907870 ） 备注 由 anygen.io 辅助整理 如果觉得有用，欢迎点赞、转发和收藏。下期见~ 有了 AI 的加持

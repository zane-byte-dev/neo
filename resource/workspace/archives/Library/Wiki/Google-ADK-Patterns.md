# Google Agent Development Kit (ADK) 5 种核心技能设计模式

这篇文章介绍了 Google Agent Development Kit (ADK) 中 5 种核心的 Agent 技能设计模式。其核心观点是：**Agent 开发的重心已从“格式规范”（YAML/目录结构）转向“内容逻辑设计”**。

以下是 5 种模式的总结与见解：

### 1. 核心模式总结

*   **Tool Wrapper (工具封装器)**
    *   **逻辑**：将特定库或框架的知识（如 FastAPI 规范）打包，仅在需要时动态加载。
    *   **价值**：避免系统提示词（System Prompt）臃肿，实现知识的按需加载。
*   **Generator (生成器)**
    *   **逻辑**：通过 `assets/` 模板和 `references/` 风格指南，强制 Agent 执行“填空式”生成。
    *   **价值**：解决 Agent 输出格式不稳定的痛点，确保结构化文档的高度一致性。
*   **Reviewer (审查者)**
    *   **逻辑**：将“检查标准”与“检查逻辑”分离。Agent 加载外部评分表（Rubric）对内容进行分级（Error/Warning/Info）审计。
    *   **价值**：模块化审计能力，更换一个 checklist 即可让 Agent 从“代码审查”切换到“安全审计”。
*   **Inversion (反转模式)**
    *   **逻辑**：强制 Agent 扮演面试官。在收集齐所有预设阶段的信息前，严禁开始生成结果。
    *   **价值**：对抗 LLM 的“急于生成”本能，确保复杂任务的上下文充分。
*   **Pipeline (流水线)**
    *   **逻辑**：定义严格的顺序工作流，并设置“人工确认”或“自动化检查”的关卡（Gate）。
    *   **价值**：处理高复杂度任务，防止 Agent 跳步或忽略中间指令。

### 2. 核心见解

*   **从“提示词工程”转向“软件工程”**：这些模式本质上是将传统的软件设计思想（如解耦、模板模式、状态机）引入 Agent 开发。开发者不再是写一段长长的咒语，而是在构建一套可预测的逻辑流。
*   **渐进式上下文加载 (Progressive Disclosure)**：通过这些模式，Agent 仅在特定步骤加载特定参考文件。这不仅节省了 Token 成本，更重要的是减少了无关上下文对 Agent 推理的干扰，提高了任务成功率。
*   **模式的可组合性**：文章强调模式不是孤立的。例如，一个 **Pipeline** 的第一步可以是 **Inversion**（收集需求），最后一步可以是 **Reviewer**（质量检查）。这种组合能力是构建生产级 Agent 的关键。
*   **确定性 vs 灵活性**：这些模式在试图给 LLM 的随机性“套上枷锁”。对于企业级应用，**Generator** 和 **Pipeline** 提供的确定性往往比 LLM 自发的灵活性更重要。

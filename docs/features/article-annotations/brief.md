# Article Annotations

## Background

Neo 当前已经在文章阅读体验上做了一轮“编辑器优先”重构：摘要被移到正文上方，AI 改写入口被移到编辑器更多菜单，资源能力也有了编辑器内入口。

但“笔记”仍然停留在资源面板里的独立列表形态，没有真正贴着文章正文发生。用户在阅读时如果想记录一段话的想法、问题或判断，仍然需要跳到单独的 Notes 视图，先起标题、再写内容，最后再自己记住这条笔记是在文章哪里产生的。

这导致文章笔记虽然“存在”，但没有形成自然工作流，最终会被用户感知为边缘功能，甚至接近废弃状态。

相关来源：

- [doc-assistant-redesign/brief.md](../doc-assistant-redesign/brief.md)：已经把摘要和部分 AI 能力移回文章编辑器，说明产品方向正在从“侧边工具面板”回到“正文内体验”。
- 用户反馈：当前“文章笔记”体验接近废弃，更合理的方向是做成文章内展示，例如划线笔记、段落笔记或评论。

## Evidence And Freshness Check

本 Brief 先基于当前代码状态做了核验，确认问题不是“缺少笔记功能”，而是“笔记形态与阅读场景错位”。

### 1. 摘要已经进入正文，说明文章内呈现是被验证过的方向

- `web/src/components/NoteEditor.tsx` 当前已经内置 `summaryState`、`handleGenerateSummary()` 和摘要卡片状态，摘要直接显示在文章标题下方。
- 这说明团队已经接受一个关键判断：与文章理解强相关的信息，应该优先在正文中出现，而不是继续藏在侧边抽屉里。

### 2. 笔记入口仍然在资源面板里，不在正文阅读流中

- `web/src/components/notebook/ResourcesPanel.tsx` 当前通过“添加笔记”按钮跳转到 `NotesTab`。
- `web/src/components/notebook/studio/NotesTab.tsx` 当前主要是“新建独立笔记 / 编辑笔记 / 合并 / 大纲 / 反馈 / 学习指南”。

结论：当前笔记系统更像“附属卡片集合”，不是“对这篇文章某一段内容的批注”。

### 3. 当前笔记数据模型没有正文锚点

- `web/src/types/index.ts` 里的 `NotebookNote` 当前只有 `id / title / content / source / createdAt / updatedAt`。
- `src/services/notebook-service.ts` 中的 `NotebookNote` 也仅围绕独立 markdown 文件保存，没有 `articleId`、`paragraphId`、`quote`、`anchor`、`resolved` 等字段。

结论：从数据层看，当前系统存的是“独立笔记文档”，不是“正文内批注”。

### 4. 编辑器已经有高亮能力，但高亮还不是批注系统

- `web/src/components/NovelEditor.tsx` 当前的气泡菜单里已支持 `toggleHighlight()`。
- 但这只是编辑器格式能力，尚未与笔记实体、评论内容、跳转定位或批注列表关联。

结论：前端交互并非从零开始，但缺少一层“持久化批注模型”。

### 5. 当前系统没有评论线程或段落注释实现

- 当前代码未发现与文章段落评论、批注线程、正文锚点跳转相对应的组件或路由。
- 这意味着“做成评论/批注”不是改文案，而是一次明确的产品与数据模型升级。

## User Problem

用户阅读一篇文章时，真正需要记录的通常不是一篇新的独立笔记，而是：

- 这句话值得标出来。
- 这一段我有疑问。
- 这里和另一篇文章矛盾。
- 这段可以 later 变成行动项、写作素材或讨论点。

当前独立 Notes 列表的问题在于：

- 记录动作脱离正文，打断阅读。
- 笔记与原文位置断开，回看时很难理解上下文。
- 笔记需要手动起标题，额外增加操作成本。
- 用户最终会减少使用频率，因为它不像“顺手一记”，更像“另开一个文档”。

## Goals

- 让“记笔记”成为文章阅读过程中的原生动作，而不是切换到另一个面板后的次级动作。
- 支持两类高频批注：划线批注、段落批注。
- 让文章仍然是主界面，批注列表只是辅助视图。
- 保留现有笔记体系的可搜索、可导出、可 AI 处理价值，但不再让它承担主入口。
- 为未来的“评论线程 / 协作讨论 / AI 汇总批注”预留可扩展的数据模型。

## Non-goals

- 本轮不做完整社交评论系统，不支持 @mention、权限角色或多人实时协作。
- 本轮不做复杂的批注颜色管理、标签体系或拖拽排序。
- 本轮不要求移动端一开始就达到桌面端完整体验。
- 本轮不立即废弃现有 `NotesTab`，而是先把它降级为辅助入口。
- 本轮不先做自动化的“每条批注都触发 AI 总结”流程。

## Target Users And Scenarios

目标用户：

- 阅读长文并持续做知识沉淀的个人用户。
- 用 Neo 管理资料、做研究或写作准备的用户。
- 需要把“文章中的具体片段”转成想法、问题和后续行动的用户。

核心场景：

1. 用户选中一句话，点击“批注”，自动生成划线并写下一段想法。
2. 用户将鼠标移到某个段落旁边，点击“+”快速添加段落批注。
3. 用户阅读过程中看到已有批注标记，点击即可查看原先记录的上下文。
4. 用户打开“全部批注”面板，按文章顺序回看并跳转到对应位置。
5. 用户完成处理后把某条批注标记为“已解决”，默认折叠但可回看。

## Proposed Experience

### 1. 产品命名与定位

建议首选名称使用“批注”而不是“评论”。

原因：

- “批注”更符合个人阅读和知识沉淀语境。
- “评论”更容易让用户联想到公开讨论区或社交互动。
- 后续如果确实需要多人协作，再把“评论线程”作为批注的一种扩展形态更稳妥。

建议对外主名称：文章批注（Article Annotations）。

### 2. 批注类型

首版建议支持三种层级，但只把前两种作为主路径：

- 划线批注：用户选中文本后添加，适合针对句子或短段落。
- 段落批注：用户不必精确选区，直接对一个段落块添加说明。
- 页面笔记：保留现有独立笔记能力，作为整篇文章的补充说明，而非正文批注主入口。

产品判断：

- 划线批注解决“这句很重要”。
- 段落批注解决“这一段值得展开聊”。
- 页面笔记解决“我对整篇文章还有一个更大的总结”。

### 3. 主入口设计

正文内主入口建议有两套：

#### A. 选区入口

- 用户选中文本后，在现有 bubble menu 中新增“批注”动作。
- 点击后弹出轻量批注卡片：默认展示所选文本摘要或引用，并提供一个输入框。
- 保存后：原文以轻量下划线标记，且标记可回到批注实体。

#### B. 段落入口

- 鼠标 hover 段落左侧或右侧时，显示一个低干扰的“+ 批注”按钮。
- 点击后在该段旁边打开一个小卡片，让用户输入内容。
- 段落上存在批注时，显示标记点或计数，而不是强行长期展开全部内容。

### 4. 正文内呈现

建议正文内采用“轻标记 + 按需展开”的模式，而不是像论坛评论那样默认全部撑开。

推荐表现：

- 划线批注：选区使用轻量下划线，不使用大面积背景高亮；hover 时在文档右侧显示对应批注卡片。
- 段落批注：段落边缘显示一个小标记点或批注气泡图标。
- hover 或点击标记后，在文档右侧 rail 展示卡片，不默认把正文挤成评论流。
- 已解决批注默认弱化，仅在 hover 或筛选时完整显示。

这样可以避免正文被大量批注卡片撕碎，同时保留“这里有上下文信息”的提醒。

### 5. 辅助面板：全部批注

现有 `NotesTab` 不应继续承担“创建批注”的主入口，而应转为“全部批注 / 页面笔记”的汇总视图。

建议重构后的辅助面板能力：

- 按文章顺序列出当前文章全部批注。
- 支持筛选：全部 / 未解决 / 已解决 / 划线 / 段落。
- 点击一条批注可跳回正文对应位置。
- 支持把批注导出为独立笔记，或做 AI 汇总。
- 页面笔记仍可保留在同一面板中，但应与正文批注清晰分组。

### 6. 与现有独立笔记系统的关系

本次不是立刻删除 `NotebookNote`，而是重新定义其角色。

建议短中期策略：

- 现有独立笔记保留，避免破坏已有数据。
- 新的正文批注使用独立实体，不复用当前 `NotebookNote` 结构。
- 提供“将批注转为独立笔记”的动作，兼容现有 quick actions 和 source 转换流程。
- 等正文批注稳定后，再评估是否需要把部分旧笔记迁移为“页面笔记”。

### 7. 数据模型建议

新增 `Annotation` 实体，至少包含以下字段：

- `id`
- `articleId`
- `notebook`
- `kind`：`highlight` | `paragraph`
- `quote`：当前选中文本或段落摘要
- `anchor`
- `body`
- `status`：`open` | `resolved`
- `author`
- `createdAt`
- `updatedAt`

其中 `anchor` 不建议只存绝对字符偏移，至少应组合以下信息：

- `paragraphId` 或 block 标识
- `startOffset / endOffset`
- `beforeText / afterText`

原因：文章会被编辑，单纯依赖绝对位置会让批注在改稿后快速失效。

### 8. 推荐 MVP 路线

建议分三步推进，而不是一次做满：

#### Phase 1：段落批注 MVP

- 给正文段落加“添加批注”入口。
- 支持新建、查看、删除、跳转。
- 支持“未解决 / 已解决”状态。
- 提供一个最简“全部批注”面板。

这样能最快验证“正文内批注”是否会显著提高使用率。

#### Phase 2：划线批注

- 在选区 bubble menu 增加“批注”。
- 保存后对选中文本持久化下划线标记。
- 支持 hover 和跳转。

#### Phase 3：增强能力

- 支持单条批注下的回复线程。
- 支持 AI 汇总未解决批注。
- 支持把批注批量转为独立笔记或来源。

## Acceptance Criteria

- 用户在已保存文章中，无需离开 `NoteEditor` 即可创建至少一种正文内批注。
- 当前文章存在批注时，正文内有明确但不过度打扰的可视标记。
- 用户刷新页面后，批注仍能正确显示并定位到对应文章内容。
- “全部批注”视图可以列出当前文章的批注，并支持跳转回正文位置。
- 数据模型层支持正文锚点，不再只保存 `title + content` 形式的独立笔记。
- 现有独立笔记能力仍然可访问，不因正文批注上线而直接丢失。
- 至少支持“打开 / 已解决”两种批注状态。

## Risks And Dependencies

- `NovelEditor` 当前以 Markdown 作为存储格式，正文改动后如何稳定重定位批注，是首个核心技术风险。
- 如果正文批注默认全部展开，长文会迅速变得嘈杂，因此必须控制默认密度。
- 当前 `NotebookNote` API 与存储模型不适合直接承接正文批注，预计需要新增服务、路由和类型定义。
- 如果未来要支持多人共享批注，还需要额外的身份与权限语义；这不应在首版强行并入。
- 若直接把“评论线程”作为首版目标，复杂度会明显高于“个人批注”，应避免 scope 过大。

## Priority

P1。原因不是“笔记功能缺失”，而是当前笔记形态没有进入核心阅读流，已经开始影响文章能力的真实使用率。

建议优先级排序：

1. 段落批注 MVP
2. 划线批注
3. 辅助面板与 AI 汇总增强

## Open Questions

- 首版批注应默认是纯个人私有，还是跟随 notebook 共享？
- “已解决”批注默认隐藏、折叠，还是继续显示为弱状态？
- 划线批注是否需要一开始就支持多颜色，还是先统一单色？
- 页面笔记是否保留在同一个面板里，还是单独分组展示？
- 批注是否需要进入统一知识索引与搜索结果中？

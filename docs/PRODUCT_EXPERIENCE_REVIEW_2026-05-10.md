# Neo 产品深度体验报告（文档工作者视角）

## 1. 体验范围与方式

本次体验目标是“启动当前项目并提供完整服务”，并以资深文档工作者的视角完成端到端走查。

已完成：
- 启动后端服务：`npm run dev:bot`（成功启动在 `http://localhost:3000`，首次运行自动生成 webToken）
- 启动前端服务：`npm run web:dev`（成功启动在 `http://localhost:5173`）
- 完成认证与服务可用性冒烟：`/api/auth/login`、`/api/me`、`/api/sessions`
- 通读关键体验链路源码：登录、侧栏导航、聊天区、Notebook、设置页（Models/Skills/Apps/MCP/Automations）

说明：本沙箱环境下浏览器自动化实例存在占用冲突，未能完成 Playwright 全 UI 点选；因此本报告采用“服务实跑 + API 冒烟 + 前端主链路源码走查”联合评估。

---

## 2. 总体结论（TL;DR）

Neo 已具备“可立即投入个人 AI 工作流”的产品底盘：
- 功能广度足（Chat / Notebook / Skills / Tools / MCP / 自动化 / Telegram）
- 架构清晰（单端口服务、后端路由自动发现、前端模块化）
- 文档基础扎实（README 与目录结构清楚，首次启动体验顺畅）

但当前“新用户首日体验”和“复杂能力可理解性”仍有明显优化空间：
- 信息密度高，关键路径提示不足
- 设置项较多但分层引导不够
- 部分交互反馈与确认机制不一致

结论：这是一个能力强于界面表达的产品，建议通过“任务导向文档 + 轻量引导 + 关键操作一致性”把能力转化为更低门槛的用户价值。

---

## 3. 体验亮点

1. **首次启动友好**
   - 自动生成默认用户与 token，并打印登录信息，降低了启动门槛。

2. **产品能力覆盖完整**
   - 从会话到知识库，再到自动化与扩展工具链，具备完整的个人 AI 工作台雏形。

3. **设置中心结构合理**
   - Models/Skills/Apps/MCP/Automations 的分组符合高级用户心智，扩展能力清晰。

4. **Notebook 与 Chat 有联动基础**
   - 支持从知识库进入对话语境，是长期知识沉淀的关键能力。

5. **工程实现可维护性较好**
   - 路由与工具自动发现、模块边界清晰，便于持续演进与贡献。

---

## 4. 主要问题与风险（按优先级）

## P0（优先立即处理）

1. **关键行为确认机制不统一**
   - 侧栏批量删除仍使用原生 `window.confirm`，与系统内 `ConfirmDialog` 体系不一致。
   - 风险：体验割裂、样式不统一、国际化与可访问性难统一。

2. **当前仓库基线验证非全绿**
   - `npm test` 存在 3 个失败用例；`web` 构建存在 TypeScript 报错。
   - 风险：影响对“完整服务稳定性”的信心，也提高新贡献者理解成本。

## P1（建议近期处理）

3. **新用户任务导向引导不足**
   - 用户已能登录，但“下一步做什么（配置模型→发起首次问答→沉淀到 Notebook）”缺少分步引导。

4. **高级能力暴露较早，学习曲线偏陡**
   - MCP、自动化、Apps 等对新手信息量较大，缺少“基础/高级”分层入口。

5. **错误提示可行动性不足**
   - 部分失败仅提示错误，不总是给出下一步操作建议（如“去哪个页面修复、需要填什么”）。

## P2（可中期优化）

6. **文档到界面的双向映射不够强**
   - README 很完整，但界面中的关键名词与文档章节映射还可更直接。

7. **“我现在是否配置正确”缺少显式健康检查面板**
   - 用户需要自行推断模型、密钥、运行时状态是否 ready。

## 5. 改进建议

## 5.1 产品交互建议

1. **增加“首次使用清单（First-run Checklist）”**
   - 放在登录后首页显著位置，默认包含：
     - 配置至少一个模型
     - 发送第一条消息
     - 创建第一条 Notebook 笔记
     -（可选）启用自动化任务

2. **设置页做“基础/高级”分层**
   - 基础：Models（含凭据）+ Skills
   - 高级：Apps + MCP + Automations
   - 通过折叠或标签分级降低新手认知负担。

3. **统一所有危险操作确认交互**
   - 全面收敛到统一确认弹窗组件，统一文案、按钮语义、危险色与快捷键行为。

4. **错误提示增加“修复建议”**
   - 每类常见错误附带“下一步动作”和“跳转入口”。

5. **增加“系统状态”卡片**
   - 展示：后端连接状态、模型可用状态、当前用户与工作目录、最近一次自动任务状态。

## 5.2 文档体系建议

1. **新增《10 分钟上手任务流》**
   - 以任务为中心而非功能罗列：
     1) 登录
     2) 配模型
     3) 发起对话
     4) 保存知识
     5) 建立自动化

2. **新增《故障排查速查》**
   - 把高频问题前置：
     - 登录失败
     - 模型不可用
     - 前后端端口冲突
     - 认证 Cookie 问题

3. **增加“界面术语对照表”**
   - README 名词与 UI 名称一一对应，减少理解摩擦。

4. **为高级能力补“最小可运行示例”**
   - MCP / Apps / Automations 各给一个“最小配置 + 预期结果”。

---

## 6. 建议实施顺序（务实版）

1. 先补全基线稳定性（测试与前端构建问题）。
2. 上线首屏 checklist 与设置分层（降低新用户流失）。
3. 统一确认弹窗与错误提示模板（提升一致性）。
4. 补齐任务流文档与故障排查文档（降低支持成本）。

---

## 7. 一句话评价

Neo 已经具备“强能力、可扩展、可自托管”的优秀内核；下一阶段应聚焦“把复杂能力表达得更简单”，让新用户在第一天就能形成正反馈闭环。

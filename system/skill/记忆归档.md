# 💾 记忆归档

> **目标**：对话结束时，自动将本次对话压缩归档，并分发资产到对应位置。

## 🛠️ 触发时机

**主触发**：
- 用户明确说"先这样"、"就这样"、"下次聊"等收尾信号。
- 一段完整任务结束时（如重构完成、审计完成）。

**补偿触发**：
- 每次对话启动时，检查 `history/memory/` 最近的文件。如果发现上次对话没有存档（比如用户直接关了终端），根据当前上下文判断是否需要补档。

## 📋 执行步骤

### 1. 压缩对话摘要

把本次对话压缩成 3-5 行，追加到当天的 memory 文件：

**路径**：`history/memory/YYYY-MM-DD.md`

**格式**：
```markdown
## HH:MM 主题关键词
- 干了什么（动作+结果）
- 产出了什么文件
- 遗留什么待办
```

**规则**：
- 只记事实，不升华
- 一条摘要不超过 5 行
- 同一天的多次对话追加到同一个文件
- 每天自动新建文件，不跨天

### 2. 资产分发

扫描本次对话，判断是否产生了需要归档的资产：

| 资产类型 | 目标位置 | 判断标准 |
|---------|---------|---------|
| 财务/交易记录 | 对应 `project/*/changelog.md` | 涉及金额、买卖、损益 |
| 原则/认知更新 | `project/wiki/Principles.md` | 产生了新的行为准则 |
| 项目进展 | `project/` 对应子目录 | 涉及具体项目的设计、决策、代码 |
| 工作记录 | `project/work/` | 涉及主业任务、发布、故障 |

如果有，直接写入对应文件。没有则跳过。

### 3. 日志同步

如果本次对话内容足够重要（不是简单问答），同步一条记录到 `history/memory/YYYY/YYYY-MM.md`。

## ⚠️ 禁止清单

- ❌ 不要问用户"是否需要存档"，直接判断并执行
- ❌ 不要存档纯闲聊、纯技术问答（如"JS 的 async 怎么用"）
- ❌ 不要重复存已经存过的内容

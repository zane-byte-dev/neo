### Neo
> 在 Gemini CLI 中，Session（会话）管理主要分为内置功能和当前环境的自定义工具两部分：
> 
> ### 一、 内置 Session 管理
> 
> **1. 恢复与查看**
> *   **启动时恢复最新会话:** `gemini --resume` (或 `-r`)
> *   **恢复指定会话:** `gemini --resume <索引或ID>`
> *   **交互式浏览:** 在 CLI 运行中输入 `/resume`，可搜索和选择历史会话。
> *   **列出所有会话:** 退出状态下运行 `gemini --list-sessions`。
> 
> **2. 手动分支 (Checkpointing)**
> *   **保存当前状态:** `/chat save <标签名>` (如 `/chat save init`)
> *   **列出所有标签:** `/chat list`
> *   **恢复到标签:** `/chat resume <标签名>`
> *   **删除标签:** `/chat delete <标签名>`
> 
> **3. 回溯与撤销**
> *   **回溯历史:** 输入 `/rewind` 或连按两次 **Esc**，可选择仅回溯对话或同时撤销代码更改。
> *   **恢复文件:** 输入 `/restore` 可将项目文件和对话状态恢复到某次工具执行前。
> *   **压缩上下文:** 输入 `/compress` 可将当前会话浓缩为摘要，节省 Token。
> 
> ### 二、 当前环境自定义工具
> 
> 当前工作区配置了专门的 Session 处理工具：
> *   **`archive_session`**: 归档 Gemini 会话到每日记忆文件 (`history/memory/YYYY-MM-DD.md`)，并提取语法审查记录。
> *   **`update_grammar_log`**: 从会话中提取语法审查记录，更新至英语学习日志 (`project/neo/src/English_Learning_Log.md`)。

### Neo
> 基于对当前架构（Gateway、MCPs、Refinery、Extension）和 `system/GEMINI.md` 设计原则的分析，Neo 项目目前在代码结构和系统鲁棒性上可以从以下五个维度进行优化：
> 
> ### 1. 核心逻辑解耦（去除硬编码）
> *   **现状**：`apps/gateway/src/lib/gemini-client.ts` 中存在硬编码的 Prompt（如 `[System Override]` 和时间上下文）。
> *   **优化**：遵循“配置驱动”原则，将所有 System Override 级别的指令提取到 `system/GEMINI.md` 或独立的 Skill Markdown 文件中，确保 AI 行为的修改只需更改文本，无需修改 Node.js 代码。
> 
> ### 2. 自动化脚本与 AI 能力整合 (Refinery vs MCPs)
> *   **现状**：系统维护逻辑割裂。定时任务和文件清理在 `apps/refinery`（如 `butler.ts`, `curator.ts`），而供 AI 调用的工具在 `apps/mcps`。
> *   **优化**：将 Refinery 中的自动化脚本重构为 MCP 工具。让 AI 能够主动感知系统状态并调用这些工具（例如主动执行归档、清理），将“被动定时执行”升级为“AI 智能调度”。
> 
> ### 3. 并发 Git 提交流程安全
> *   **现状**：`butler.ts` 和 `memory-server` 等多个组件可能在后台触发自动 Git Commit，在无锁状态下容易产生并发冲突（Race Conditions）。
> *   **优化**：实现一个简单的 Git 队列或文件锁（Lock 机制），集中管理所有自动化提交请求，确保本地 Git 树的绝对稳定。
> 
> ### 4. IPC 通信层鲁棒性 (Gateway <-> Gemini CLI)
> *   **现状**：Gateway 底层依赖进程标准输入输出（Stdio）进行 JSON-RPC 通信，对输出格式极度敏感。
> *   **优化**：在 `acp-client.ts` 中增强对异常输出和长文本截断的解析容错率，并加入严格的超时（Timeout）熔断机制，防止底层模型响应异常导致 Gateway 进程挂死。
> 
> ### 5. 文档与目录结构对齐
> *   **现状**：根目录 `README.md` 与实际文件结构存在偏移（如文档描述了 `tools/`，实际工程使用 `apps/` 目录）。
> *   **优化**：执行一次彻底的文档审计，同步最新的 4 层架构（UI/Gateway/Engine/Capabilities），降低后续开发的认知负担。
> 
> 如需执行其中某项优化（如重构 `gemini-client.ts` 或合并 MCP），请下达具体指令。

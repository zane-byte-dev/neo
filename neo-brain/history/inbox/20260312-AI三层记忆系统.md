> **核心观点：** 上下文窗口不等于记忆。想让 Agent 记住，必须把关键信息写进文件。文件 = 事实来源。你不写进文件的东西 = 你从来不知道的东西。

---

### 一、 为什么你的 AGENT 总在“失忆”？

很多人以为只要对话够长，模型就能一直记得。但现实是：LLM 的上下文窗口是临时工作台，不是长期记忆。

*   **压缩（Compaction）：** 对话变长后，系统会丢弃早期内容。
*   **Session 隔离：** 一旦会话结束，Agent 下次“醒来”就像重启一样。
*   **多渠道孤岛：** Telegram、Discord、微信等渠道之间互不相通。

**实战案例：**
*   Session 1：做了重要决策 A → 没写进文件 → 被压缩丢弃。
*   Session 2：Agent 不知道决策 A → 重复讨论 → 浪费时间。

**原则：** 把 Agent 的“记忆”从脑子里，搬到磁盘上。

---

### 二、 整体思路：三层记忆 + 一个“主动遗忘”机制

系统将信息分层管理：
1.  **短期：** `NOW.md`（工作台状态）
2.  **中期：** 每日记忆日志（事件流水）
3.  **长期：** 可复用知识库（Lessons/Decisions/People…）

**关键机制：** 定期归档冷数据（主动遗忘），确保系统不过载、可检索、可持久化。

---

### 三、 短期记忆：NOW.md（唯一允许覆写的文件）

`NOW.md` 是状态面板，用于对抗上下文压缩。

*   **操作：** 每次 heartbeat（心跳任务）直接覆写，不追加。
*   **内容：** 只保留“今天必须知道”的目标、重点、卡点。

#### 示例模板：
```markdown
# NOW.md - Workbench

> **Mission**: 你的核心目标

## Today (MM/DD)
- ✅ 已完成的重要事项
- ⚠️ 需要关注的问题

## P0 Priorities
| # | Item | Status | Owner |
|---|------|--------|-------|
| P0 | 最重要的事 | 进行中 | Agent A |
| P1 | 次重要的事 | 待开始 | Agent B |

## Agent Status
| Agent | Focus |
|------|-------|
| Agent A | 当前任务 |
| Agent B | 当前任务 |

---
*Updated: YYYY-MM-DD HH:MM*
```

---

### 四、 中期记忆：每日日志（Append-only，永不覆写）

每日日志是“发生了什么”的原始流水账。

*   **路径：** `memory/YYYY-MM-DD.md`
*   **规则：** 只追加、不覆写。记录事件、完成情况、变更与发现。
*   **意义：** 解决 Session 隔离问题，作为人与 Agent 的共同证据。

---

### 五、 长期记忆：知识库（可复用的“蒸馏层”）

从日志中提炼出的“可复用知识”，通过 `memory/INDEX.md` 作为导航枢纽。

#### 目录结构建议：
*   `decisions/`：重要决策（永久保留）
*   `lessons/`：经验教训（按主题沉淀）
*   `people/`：用户/Agent 画像、联系人
*   `projects/`：项目状态
*   `preferences/`：偏好与边界
*   `reflections/`：每日反思

#### 关键技巧：
1.  **元数据（Frontmatter）：** 为文件添加标题、日期、优先级、状态（active/superseded）和标签。
2.  **CRUD 验证：** 写入前先读。避免重复、矛盾或幻觉。根据情况选择跳过、新增、更新或标记冲突。

### 六、 自动化工具：memlog.sh 脚本

手动记录易出错，推荐使用自动化脚本追加带时间戳的日志。

```bash
#!/usr/bin/env bash
# memlog.sh — 自动时间戳的日志追加工具

set -euo pipefail

MEMORY_DIR="${MEMORY_DIR:-/path/to/workspace/memory}"
TODAY=$(TZ=Asia/Shanghai date +%Y-%m-%d)
NOW=$(TZ=Asia/Shanghai date +%H:%M)
FILE="$MEMORY_DIR/$TODAY.md"
TITLE="${1:?Usage: memlog.sh \"Title\" \"Body\"}"
BODY="${2:-}"

if [[ ! -f "$FILE" ]]; then
  printf "# %s\n" "$TODAY" > "$FILE"
fi

{
  printf "\n### %s — %s\n" "$NOW" "$TITLE"
  [[ -n "$BODY" ]] && printf "\n%s\n" "$BODY"
} >> "$FILE"

echo "✓ Logged to $TODAY.md at $NOW"
```

### 七、 为什么必须“让记忆会衰减”（主动遗忘）

遗忘不是 bug，是 feature。如果不做衰减，检索噪音会变大，系统会变慢。

**做法：引入“温度（Temperature）”概念**
*   **热（Hot）：** 新、常引用、高优先级 → 保留在活跃索引。
*   **温（Warm）：** 较旧但可能有用 → 保留但降权。
*   **冷（Cold）：** 很旧且未引用 → 移入 `.archive/`（隐藏目录，不参与索引）。

---

### 八、 最小可用版本（MVP）落地步骤

1.  **阶段 0：** 准备 `NOW.md`、`AGENTS.md`（规则说明）和 `memory/YYYY-MM-DD.md`。
2.  **第 1 周：** 增加 `INDEX.md` 及 `lessons/`、`decisions/` 目录。
3.  **第 2 周：** 引入 Frontmatter 和每晚反思（提炼知识）。
4.  **第 3 周：** 增加语义搜索与 GC（归档机制）。
5.  **第 4 周：** 实现多 Agent 记忆聚合。

### 结语

把“记忆”当成基础设施。上下文只是工作台，文件才是事实仓库。写入要自动化，知识要验证，系统要会遗忘，才能长期高效。
